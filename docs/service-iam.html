🔐 AWS IAM

Identity and access management - who can do what on which resources across your AWS accounts.

Contents

Core Concepts Policy Evaluation Roles & Federation Best Practices Exam Tips Related

Core Concepts

  • Users / Groups - long-term identities (avoid for apps).
  • Roles - temporary credentials assumed by services/users.
  • Policies - JSON documents (identity-based, resource-based).
  • Principals - the entity making a request.

Policy Evaluation

  • Default is implicit deny.
  • An explicit Deny always overrides any Allow.
  • Order: explicit Deny > SCP > resource/identity Allow > implicit deny.
  • Permission boundaries cap a principal's max permissions.

Roles & Federation

  • Instance profiles - roles for EC2.
  • STS AssumeRole - cross-account and temporary access.
  • Identity federation - SAML, OIDC, IAM Identity Center.
  • Web identity - Cognito for mobile/web apps.

Best Practices

  • Least privilege; use roles over long-term keys.
  • Enable MFA, especially on root; lock away root.
  • Use IAM Access Analyzer to find overly broad access.
  • Rotate credentials; prefer temporary via STS.

🎓 Exam Tips

⚠ Frequently tested
  • An explicit Deny always wins - even over an Allow in another policy.
  • Use IAM roles for EC2/Lambda; never embed long-term access keys.
  • SCPs limit maximum permissions org-wide but never grant access by themselves.
  • Permission boundaries cap what a principal can do, useful for delegated admin.
  • Cross-account access = a role in account B trusts account A via sts:AssumeRole.
