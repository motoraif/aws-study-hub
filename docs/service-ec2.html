🖥️ Amazon EC2

Resizable virtual servers in the cloud - the foundational compute service behind much of AWS.

Contents

Core Concepts

  • Instance types - families for general (M/T), compute (C), memory (R/X), storage (I/D), accelerated (P/G).
  • AMI - template for the root volume + launch permissions.
  • Instance metadata (IMDS) - 169.254.169.254; prefer IMDSv2.
  • User data - bootstrap script run at first boot.

Pricing Models

ModelUse
On-DemandShort-term, unpredictable
Reserved / Savings PlansSteady, 1-3 yr commit, big discount
SpotInterruptible, up to 90% off
Dedicated Hosts/InstancesCompliance, licensing

Storage & Networking

  • EBS - persistent block volumes (gp3, io2, st1, sc1).
  • Instance store - ephemeral, high IOPS, lost on stop.
  • ENI / EIP - virtual NIC / static public IP.
  • Placement groups - cluster (low latency), spread, partition.

Auto Scaling & HA

  • Auto Scaling Groups - min/desired/max; scale on metrics.
  • Launch templates - versioned instance config.
  • ELB health checks vs EC2 status checks.
  • Spread across AZs for fault tolerance.

🎓 Exam Tips

⚠ Frequently tested
  • Spot is best for fault-tolerant, interruptible work; never for stateful single instances.
  • Use IMDSv2 (token-based) to mitigate SSRF attacks against instance metadata.
  • gp3 lets you provision IOPS/throughput independently of size (cheaper than gp2 often).
  • Auto Scaling + ELB across multiple AZs is the standard HA answer.
  • Placement groups: cluster = lowest latency, spread = max fault isolation.
